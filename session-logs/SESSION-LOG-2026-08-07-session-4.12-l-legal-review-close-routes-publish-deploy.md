## 3. Defects caught and fixed — specific

1. **Shell-quoting bug in the executor's own verification script.** An ad-hoc Node diff
   script passed via `bash -c "node -e '...'"` had single quotes inside its JS string
   literals (e.g. `.replace(/&#39;/g, "'")`), which terminated the outer single-quoted
   bash argument early. The mangled script partially executed, and its own leaked source
   code was misread as a genuine content mismatch in the built HTML. Caught before being
   reported as a real finding; re-run correctly as a script file (`/tmp/verify_html.js`),
   which returned a clean, correct `EXACT_MATCH=true` for both files. Recorded as a live
   instance of "verify the edit, don't trust the tool's own output" applying reflexively
   to the verifier's own tooling.
2. **Mojibake false alarm.** Yehor's `Get-Content` output showed `вЂ”` where a `—` em
   dash was expected in the page `<title>` metadata. Investigated via direct hex dump of
   both the source `page.tsx` and the actual built `privacy.html`'s `<title>` tag: both
   contain the correct UTF-8 byte sequence `e2 80 94`. Root-caused to PowerShell's
   console codepage (consistent with a Cyrillic/CP1251-configured Windows locale
   misreading UTF-8) rather than any real file corruption — not a defect, but worth
   ruling out with evidence rather than asserting confidently.
3. **`pnpm dev` instruction error (Node 1's own).** Told Yehor to run `pnpm dev` from
   the monorepo root; the root `package.json` has no `dev` script, only `web/package.json`
   does. Corrected to `cd web; pnpm dev`. Minor, self-corrected, no downstream impact.

No defects were found in the shipped content itself (routes, public-edition documents,
the KV TTL code) beyond the verification-tooling issues above.
