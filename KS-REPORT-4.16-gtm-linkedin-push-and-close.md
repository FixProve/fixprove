   confirmed ~6 times this session) but now ~85 stale lock files accumulated in `.git/`
   since 2026-07-21. Not fixed this session — flagged as a cleanup candidate, not urgent.

## 6. Methodology note

This session's most useful catch was procedural, not substantive: a close-out process
that re-reads a file's own history before trusting a bulk git operation on it caught a
real mistake before it went public. The lesson generalizes past this one file — any
append-only register accumulating "hold until decided" entries needs its own history
re-read before a session treats "it's modified, let's commit it" as safe by default.
